장바구니에서 수량을 바꿨는데 상품 위치까지 바뀌면, 사용자는 방금 보고 있던 항목을 다시 찾아야 합니다. 사용자 인터뷰에서 장바구니를 적극적으로 쓰는 사람들이 기존 정렬을 불편하게 느낀다는 맥락이 나왔습니다.

저는 최근 활동을 정렬에 반영하되 모든 수정을 같은 활동으로 보지는 않기로 했습니다. **새로 담기와 이미 담은 상품의 수량 변경은 화면에서 기대하는 결과가 달랐습니다.**

## updated_at 하나로 의도를 표현할 수 없었다

최근 담은 브랜드 묶음을 위로 올리려면 최신 활동 시각이 필요합니다. 하지만 ORM의 `auto_now`는 수량·옵션 수정에도 시각을 갱신합니다. 이를 그대로 정렬에 쓰면 수정만 해도 묶음이 움직입니다.

그래서 상품 상세에서 직접 담는 요청은 브랜드 묶음의 시각을 갱신하고, 장바구니 안의 PATCH는 기존 정렬 시각을 보존했습니다. 저장 부수효과는 유지하면서 정렬에 쓰는 시각만 복원하는 경로를 뒀습니다.

| 행동                        | 화면에서 유지할 의도         |
| --------------------------- | ---------------------------- |
| 상품 상세에서 새로 담기     | 최근 관심 브랜드를 위로 이동 |
| 장바구니에서 수량·옵션 수정 | 보던 위치 유지               |
| 정렬을 보존하며 추가        | 기존 상품 주변에 배치        |

정렬 보존 추가는 기존 요청에 플래그를 계속 붙이는 대신 별도 엔드포인트로 분리했습니다. 호출하는 쪽에서 어떤 행동인지 드러나게 했습니다.

## 옵션 하나의 품절이 브랜드 전체를 밀어내면 안 됐다

기존 판정에는 옵션과 상품 단위 품절 기준이 섞여 있었습니다. 한 옵션이 품절이어도 다른 옵션을 구매할 수 있는데 브랜드 묶음 전체가 내려가면 구매 가능한 상품까지 찾기 어려워집니다.

상품이 어떤 옵션으로도 구매 불가능한지를 공통 함수에서 판단했습니다. 묶음 안에서는 구매 불가 상품을 뒤로 보내고, 묶음 전체가 구매 불가일 때만 장바구니 하단으로 보냈습니다.

인터뷰에 따라 정책이 바뀔 때마다 모든 정렬 호출부를 수정하지 않도록 판정은 한곳에 모았습니다. 각 호출부는 그 결과만 정렬 키에 사용합니다.

## 순수 함수로 남긴 부분이 다음 작업에 도움이 됐다

그룹과 정렬은 DB 쓰기와 분리한 `sort_and_group_cart_items(items)`에 두었습니다. 조회한 항목을 입력하면 정렬 결과를 얻을 수 있게 했습니다.

새 옵션을 기존 상품 근처에 두는 시각 계산은 브랜드 시각 동기화와 충돌하는 경우가 있어 조정했습니다. 단순히 더 이른 시각을 넣는 방식이 다른 경로에서도 같은 위치를 보장하지는 않았습니다. 저장 경로와 정렬의 보조 기준을 함께 봐야 했습니다.

신규 테스트 47개로 품절 판정과 그룹 정렬, 정렬 보존 추가, 응답 상태를 검증했습니다. 구매 전환의 변화는 측정하지 않았습니다.

이후 [비로그인 장바구니](/posts/guest-cart-stateless-merge/)에서는 서버에 저장하지 않은 항목으로도 같은 함수를 재사용했습니다. 저장 방식이 바뀌어도 정렬 정책을 다시 쓰지 않아도 된 것은 이 작업에서 계산과 쓰기를 나눈 덕분입니다.
