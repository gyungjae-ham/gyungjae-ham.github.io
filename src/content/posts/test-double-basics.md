테스트 대상이 메일 서버나 DB를 호출하면 결과를 만들기 위해 외부 환경까지 준비해야 할 수 있습니다. 테스트 대역(Test Double)은 이 의존성을 대신하는 객체의 총칭입니다. mock은 그중 한 역할이며 모든 대역의 동의어는 아닙니다.

| 역할  | 테스트에서 하는 일                            | 예                                  |
| ----- | --------------------------------------------- | ----------------------------------- |
| Dummy | 인자를 채우되 해당 테스트에서는 사용하지 않음 | 호출되지 않는 알림 의존성           |
| Stub  | 미리 정한 응답 제공                           | 환율을 고정값으로 반환              |
| Spy   | 호출 내용을 기록해 나중에 검사                | 발송된 메일 목록 기록               |
| Mock  | 기대한 상호작용 검증                          | 특정 수신자에게 한 번 보냈는지 확인 |
| Fake  | 실제 기능의 단순한 구현 제공                  | Map 기반 저장·조회                  |

이 구분은 라이브러리 이름보다 테스트에서 맡은 역할에 가깝습니다. 손으로 작성한 객체도 mock 역할을 할 수 있고, Mockito로 만든 객체도 응답만 제공하면 stub으로 쓰인 것입니다. Spy가 반드시 실제 객체를 감싸야 하는 것도 아닙니다. Mockito의 `spy` API는 실제 객체 동작을 사용하는 구체적인 구현 방식입니다.

테스트가 여러 실제 협력 객체를 함께 쓰는 sociable 방식이어도 반드시 DB에 접속하는 것은 아닙니다. 메모리 안의 도메인 객체들을 함께 사용할 수도 있습니다. 반대로 solitary 방식은 선택한 테스트 대상을 협력자와 분리하는 데 초점을 둡니다.

분류를 외우는 것보다 이번 테스트가 확인할 결과를 정하는 것이 먼저입니다. 같은 메일 발송을 두고 어떤 대역을 고를지는 [테스트 대역 선택 예시](/posts/test-doubles-concept/)에서 이어집니다.
