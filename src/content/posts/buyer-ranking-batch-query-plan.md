쇼핑몰 홈에 구매자 수를 기준으로 상품 랭킹을 만드는 작업을 진행했습니다. 같은 사람이 여러 번 산 상품보다 여러 사람이 선택한 상품을 보여주려는 목적이었습니다. 결제 완료 주문을 대상으로 상품별 구매자를 중복 없이 세고, 일간·주간·월간 순위와 지난 기간의 확정 순위를 제공해야 했습니다.

홈을 열 때마다 주문 전체를 계산하지 않도록 배치에서 미리 순위를 만들었습니다. 현재 순위와 직전 순위 비교용 데이터는 Redis에, 기간이 끝난 확정본은 DynamoDB에 저장했습니다. 그런데 배치를 검증하면서 데이터를 만드는 쪽의 비용이 문제가 됐습니다. 주문량이 늘자 프로세스가 메모리 부족으로 종료됐고, DB의 임시 디스크 사용도 커졌습니다.

## 필요한 것은 주문 목록이 아닌 상품별 구매자 수

초기에는 주문 행을 Python으로 가져와 처리했습니다. 주문이 많아질수록 애플리케이션에 올려야 할 데이터도 늘어나는 방식이었습니다. 상품별 집계를 DB에서 수행하고 결과만 가져오도록 바꿨습니다.

예를 들어 상품 A를 고객 한 명이 두 번 사고 다른 고객이 한 번 샀다면 주문은 세 건이지만 구매자는 두 명입니다. 애플리케이션이 세 주문을 모두 읽는 대신 `상품 A, 구매자 2명`이라는 결과를 받으면 됩니다. 계산 의도를 단순화하면 다음과 같습니다. `order_items`는 결제 완료 등 필요한 조건이 적용된 QuerySet입니다.

```python
from django.db.models import Count

rows = (
    order_items.order_by()
    .values("product_id")
    .annotate(buyer_count=Count("user_id", distinct=True))
)
```

`distinct=True`는 같은 구매자를 중복해서 세지 않기 위한 조건입니다. 묶는 기준도 상품 하나로 유지해야 합니다. 상품과 주문 시각을 함께 묶으면 같은 상품이 여러 그룹으로 나뉘어 원하는 결과와 달라질 수 있습니다.

## ORM 코드와 실행되는 SQL을 함께 확인하기

집계를 DB로 옮겼다고 검토가 끝나지는 않았습니다. 생성된 SQL에 필요 없는 정렬이 남는지도 확인하고 `.order_by()`로 정렬을 비웠습니다.

여기서는 Django 버전도 구분해야 합니다. 사용 중인 3.2에서는 `Meta.ordering`이 자동으로 집계의 `GROUP BY`에 들어간다고 설명할 수 없습니다. 그 동작은 3.1부터 바뀌었습니다. 명시적으로 넣은 `order_by()`나 커스텀 QuerySet에서 추가한 정렬을 따라가야 합니다. [Django 집계와 정렬 문서](https://docs.djangoproject.com/en/3.2/topics/db/aggregation/#interaction-with-order-by)도 이 차이를 설명합니다.

쿼리 호출 횟수는 한 번이어도 DB가 읽고 정렬하는 행 수는 다를 수 있습니다. 그래서 SQL과 `EXPLAIN`을 함께 확인했습니다. 정렬 유입 경로별 비용을 나눠 측정한 전후 자료는 없어, 모델의 기본 정렬이 당시 부하의 원인이었다고 단정하지는 않습니다.

인덱스도 모델 코드만 보지 않고 `SHOW INDEX`로 실제 DB를 확인했습니다. `Meta.indexes`에는 없던 수동 추가 인덱스가 존재했습니다. 실제 구성을 기준으로 필터와 인덱스 사용을 다시 살폈고, 테스트 환경에서는 전체 스캔 대신 범위를 좁혀 읽는 range scan을 확인했습니다. CPU와 함께 임시 디스크 사용 시계열도 확인했습니다.

## 랭킹을 읽는 코드도 살펴봤습니다

집계 결과를 조회하는 상품 카드 Serializer에는 이미지 조회와 CDN 이관 작업 예약이 들어 있었습니다. 랭킹을 읽는 요청이 새로운 작업까지 만들고 있어, 이 경로는 응답 모양을 유지하면서 필요한 데이터를 읽고 직렬화하는 데 그치도록 정리했습니다.

로컬과 테스트 서버에서 집계·조회 동작과 관련 회귀 테스트를 확인했습니다. 운영 p95 개선값은 측정하지 않았습니다. 이번에 다룬 범위는 애플리케이션이 가져오는 데이터의 양, DB가 실행하는 집계 SQL, 조회 중 예약되던 추가 작업이었습니다.
