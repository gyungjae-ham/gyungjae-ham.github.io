athlog는 인스타그램 게시물을 쇼핑몰 앱 안에서 보여주는 콘텐츠 화면입니다. 운영자가 설명과 미디어를 직접 등록하던 과정을 Graph API로 읽어 S3에 저장하는 Celery 작업으로 바꿨습니다. 정기 수집과 운영자가 즉시 실행하는 기능을 함께 제공해야 했습니다.

정상 흐름은 게시물을 읽고 파일과 DB 레코드를 저장하면 됩니다. 어려운 부분은 중간에 멈췄을 때였습니다. 파일은 올라갔지만 DB 저장이 실패하거나, 정기 수집 중 운영자가 같은 수집을 시작할 수 있습니다. 실패한 위치에 따라 무엇을 다시 처리할지 정리했습니다.

## 미디어 전체를 메모리에 올리지 않기

기존 수동 등록은 클라이언트가 presigned URL로 S3에 직접 업로드했습니다. 자동 수집에서는 서버가 외부 미디어를 다운로드해야 하므로 워커의 AWS 권한으로 업로드했습니다.

응답 전체를 `BytesIO`에 담는 대신 `requests`의 streaming 응답을 `upload_fileobj`에 전달했습니다. 큰 파일을 통째로 메모리에 보관하지 않으려는 변경입니다. 다만 multipart 버퍼와 동시 업로드가 있어 워커 메모리가 단일 청크 크기만큼만 쓰인다고 보장할 수는 없습니다.

`Content-Length`로 큰 파일을 일찍 거르는 검사도 넣었습니다. 하지만 헤더가 없거나 실제 크기와 다르면 이 검사만으로 제한할 수 없습니다. 강제로 크기를 제한하려면 실제 읽은 바이트를 누적해서 검사하고, 초과 시 업로드 중단과 남은 파일 정리까지 해야 합니다.

## 두 수집 작업이 겹치면

정기 작업과 수동 실행의 겹침을 줄이기 위해 Redis 키를 원자적으로 생성하고 만료 시간을 뒀습니다. 이런 락은 작업이 만료 시간 안에 끝난다는 보장이 없다는 점을 함께 봐야 합니다.

예를 들어 작업 A가 오래 걸리는 동안 락이 만료되고 B가 새 락을 얻었다고 해보겠습니다. 뒤늦게 끝난 A가 키를 무조건 지우면 B의 락을 삭제합니다. 락마다 소유자 토큰을 두고 자기 토큰일 때만 원자적으로 해제해야 하는 이유입니다. 필요한 경우 소유권을 확인하면서 만료 시간을 연장하는 방법도 있습니다. [Redis의 락 해제 설명](https://redis.io/docs/latest/develop/clients/patterns/distributed-locks/)을 기준으로 확인할 부분입니다.

락으로 동시 실행을 줄여도 같은 게시물이 다시 수집되는 것까지 막지는 못합니다. 외부 게시물 ID의 유일성은 DB에서 보호하고, 충돌하면 기존 결과를 다뤄야 합니다. 일시적인 통신 실패는 재시도할 수 있지만 인증 만료는 같은 요청을 반복해도 해결되지 않아 별도로 알려야 합니다.

## S3 파일은 DB rollback으로 지워지지 않습니다

처리는 임시 경로 업로드, 콘텐츠 행 생성, 정식 키로 이동, 미디어 행 저장 순서로 나눴습니다. 느린 다운로드와 업로드 동안 DB 트랜잭션을 길게 유지하지 않으려는 선택입니다.

대신 각 단계의 정리가 필요합니다. 임시 업로드 후 DB 등록에 실패하면 해당 prefix의 Lifecycle 정책으로 남은 임시 파일을 정리할 수 있습니다. 하지만 이미 정식 경로로 옮긴 파일은 같은 정책의 대상이 아닙니다. S3의 이동도 복사와 삭제로 나뉘므로, 어느 단계에서 실패했는지에 따라 남는 객체가 다릅니다. 콘텐츠 행과 파일을 각각 확인해야 합니다.

수집 완료 후 공개 조건도 확인해야 했습니다. 사진만 있는 게시물과 달리 영상은 HLS 변환을 기다립니다. 운영자 승인이 필요한 콘텐츠라면 변환 완료도 공개 승인을 대신하지 못합니다. 이 상태 처리는 [HLS 변환 작업](/posts/athlog-video-hls-redesign/)과 연결했습니다.

외부 파일은 다운로드 경로뿐 아니라 허용 형식과 내용도 확인해야 합니다. 예를 들어 `image/*` 검사에는 SVG도 포함되므로 이 조건만으로 SVG가 차단됐다고 볼 수 없습니다. 호스트 허용 목록과 리다이렉트 제한도 모든 파일 검증을 대신하지는 않습니다.

한 번의 수집 실행에서는 69건을 실패 없이 처리했습니다. 이후 운영에서는 이 한 번의 결과와 별개로, 인증 만료나 중간 실패 후 빠진 게시물을 다시 처리할 수 있는지 확인해야 합니다.
