JPA에서 조회한 회원의 이름을 바꾼 뒤 별도의 UPDATE 메서드를 호출하지 않았는데 DB 값이 변경될 수 있습니다. 반대로 똑같이 setter를 호출해도 아무 SQL이 실행되지 않는 경우가 있습니다. 그 객체를 영속성 컨텍스트가 관리하고 있는지에 따라 달라집니다.

김영한님의 JPA 로드맵을 학습하면서 이 동작을 중심으로 정리했습니다. 영속성 컨텍스트는 EntityManager가 관리하는 엔티티의 상태와 동일성을 추적하는 범위입니다. 객체가 메모리에 있다는 뜻과 DB에 커밋됐다는 뜻을 구분해야 합니다.

## 조회한 객체를 바꾸면 무엇이 일어날까

아래는 활성 트랜잭션에서 기존 회원을 조회하는 예시입니다. Member 매핑과 트랜잭션 준비는 생략했습니다.

```java
Member member = em.find(Member.class, 1L);
member.setName("변경할 이름");
em.flush();
```

조회한 회원이 managed 상태라면 변경 감지 대상입니다. `flush()` 때 변경 내용을 DB와 동기화하므로 UPDATE가 실행될 수 있습니다. setter가 호출되는 순간마다 곧바로 SQL을 보내는 것은 아닙니다.

새 객체는 처음에는 비영속 상태이며 `persist()`로 관리 대상에 들어갑니다. 다만 INSERT 시점은 ID 생성 전략에도 영향을 받습니다. IDENTITY처럼 DB가 만든 식별자가 필요한 경우에는 일찍 INSERT가 실행될 수 있습니다. 관리 대상이 됐다는 사실과 SQL 실행 시점이 항상 일치하는 것은 아닙니다.

## 같은 회원을 다시 찾으면

같은 영속성 컨텍스트에서 같은 타입과 ID의 managed 엔티티는 같은 인스턴스로 관리됩니다. 앞에서 읽은 회원을 다시 `find()`하면 이미 관리 중인 객체를 사용할 수 있습니다. 이를 1차 캐시라고 설명합니다.

모든 JPQL 결과를 저장해 두는 캐시라는 뜻은 아닙니다. JPQL의 조건을 DB에서 조회하는 것과 조회 결과에 해당하는 엔티티를 같은 인스턴스로 관리하는 것은 다른 일입니다. DB의 REPEATABLE READ 격리 수준처럼 모든 검색 결과를 고정하는 기능으로 이해해서도 안 됩니다.

## flush는 저장 내용을 보내고 clear는 관리를 끊는다

`flush()`는 변경을 DB에 동기화하지만 영속성 컨텍스트를 비우지 않습니다. SQL이 실행됐더라도 트랜잭션이 롤백되면 DB 변경은 취소될 수 있습니다. commit과 같은 작업은 아닙니다.

flush는 직접 호출할 수도 있고, 커밋 과정이나 필요한 쿼리 실행 전에 일어날 수도 있습니다. 기본 AUTO 모드에서는 쿼리 결과에 영향을 주는 변경을 동기화합니다. COMMIT 모드에서는 쿼리 실행 시 미반영 변경이 결과에 어떻게 영향을 주는지 보장되지 않으므로 조회 순서를 주의해야 합니다.

반면 `clear()`는 관리하던 엔티티들을 분리합니다. 특정 객체만 분리하려면 `detach()`를 사용합니다. 이렇게 준영속 상태가 된 객체를 바꿔도 이전 컨텍스트가 변경 감지로 자동 저장해 주지는 않습니다.

```java
Member member = em.find(Member.class, 1L);
member.setName("변경할 이름");
em.flush();  // 먼저 SQL로 반영
em.clear();  // 이후 관리 중인 객체를 분리
Member reloaded = em.find(Member.class, 1L);
```

이 순서는 테스트에서 메모리의 값만 보지 않고 DB에 보낸 내용을 다시 읽을 때 유용합니다. 저장하지 않은 변경이 있는데 clear부터 호출하면 그 변경을 잃을 수 있습니다. [Repository 저장 테스트](/posts/datajpatest-feature/)에서도 이 차이를 사용합니다.

쓰기 지연 역시 JDBC 배치와는 구분해야 합니다. SQL을 flush까지 미룬다고 여러 문장이 자동으로 한 배치가 되는 것은 아닙니다. 실제 배치는 ID 전략, Hibernate 설정, 드라이버 조건을 함께 확인해야 합니다. JPA 코드를 읽을 때는 객체의 상태, SQL을 보낸 시점, 트랜잭션의 커밋을 따로 따라가면 이해하기 쉽습니다.
