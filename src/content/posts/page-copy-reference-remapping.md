> 페이지 요소에 새 UUID를 발급했는데 JSON 속 참조는 원본에 남았습니다. 복제 대상과 내부 참조를 함께 변환해 복제본의 필터와 상품 풀이 독립적으로 동작하도록 바꿨습니다.

## 객체 복사와 참조 복사는 다르다

페이지의 요소는 새로 생성되었지만 필터가 가리키는 요소와 상품 URL 일부는 원본 식별자를 사용했습니다. 복제본을 편집해도 원본에 종속되는 동작이 남았습니다. 행을 새로 만드는 것으로 복제가 완료되지 않은 사례입니다.

이 기록은 PR 설명과 변경 코드에 근거한 구현 정리입니다. 모든 대안을 미리 검토했다거나 어떤 개인적 이유로 선택했는지는 원본에 충분히 남아 있지 않아 회고로 만들지 않았습니다.

## 내부 참조만 변환할 수 있어야 했다

페이지와 숨김 필터 풀을 복제하면서 기존 ID·UUID와 새 값의 대응표를 유지했습니다. JSON을 변환할 때 대응표에 포함된 참조만 새 값으로 바꾸었습니다.

문자열에 UUID가 있다고 전부 치환하면 외부 요소나 수동으로 넣은 URL까지 바뀔 수 있습니다. 상품 URL도 복제 대상 풀에 속하는 것으로 확인된 경우만 수정했습니다. 복제본이 소유할 참조와 계속 공유할 참조를 나누는 것이 핵심입니다.

상품 순서와 노출 기간도 복사했습니다. 새 ID를 만드는 단계와 표시 계약을 유지하는 단계를 함께 처리해야, 복제 직후 같은 구성이 보입니다.

## 필요한 풀이 없으면 부분 복제를 남기지 않았다

참조한 풀이 존재하지 않으면 전체 트랜잭션을 롤백하도록 했습니다. 페이지 일부만 만들어지고 필터 참조는 끊어진 상태로 남기지 않기 위해서입니다. 실패한 복제의 어느 요소를 수동으로 지워야 하는지 운영자가 판단할 필요도 줄어듭니다.

다만 DB 트랜잭션으로 묶었다는 사실만으로 외부 저장소까지 복구되는 것은 아닙니다. 이 기록에서 확인한 범위는 페이지와 참조 풀의 DB 변경입니다. 외부 효과를 새로 만들었다고 가정하지 않았습니다.

## 변환 테스트와 API 회귀를 구분했다

PR에는 참조 변환 단위 테스트 통과가 남아 있습니다. 반면 API 회귀는 공유 DB의 컬럼 누락으로 setup 단계에서 막혔습니다. 병합은 확인되지만 이 테스트 실패가 해결되었거나 실제 운영 동작까지 확인되었다는 근거는 없습니다.

따라서 결과를 전체 복제 API의 완전한 회귀 통과로 표현하지 않았습니다. 구현에서 확인한 변화는 내부 참조를 새 객체로 연결하고 외부 참조를 보존한 것입니다. 복제는 같은 모양의 객체를 만드는 작업이면서, 새 객체가 어느 관계를 소유할지 정하는 작업이었습니다.
